# Отчёт о работе AI Coding Agent

## Область и используемый агент

Работа выполнена Copilot SDK в VS Code в ветке `copilot-work`. Отдельная копия и
ветка второго агента намеренно не открывались и не изменялись.

## Задачи и существенные запросы

Основные пользовательские запросы сводились к таким задачам:

1. изучить `HOMEWORK.md`, архитектуру проекта и восстановить требования в
   `ANALYSIS.md`;
2. исследовать и исправить установку Tinkoff Invest SDK, сохранив работу котировок
   и свечей;
3. реализовать историю цен, сохраняемую при обновлении котировок;
4. выполнить домашнее задание целиком в своей ветке, реализовав остальные функции
   задания №4, добавив тесты и проверки;
5. не изменять вторую ветку и не создавать коммиты.

Пользователь отдельно подтвердил, что агент должен работать только в своей ветке.

## Результаты и ошибки

- Добавлены ценовая история, персональный watchlist и in-app ценовые уведомления,
  виртуальные портфели с журналом операций и P/L, симулятор стратегий с журналом
  сделок.
- Исправлены маршруты пользовательских страниц, ошибки формы регистрации/входа и
  интервал Celery Beat: имя «каждые 5 минут» теперь соответствует 300 секундам.
- Исправлена установка старого Tinkoff SDK: инструкция использует закреплённый
  commit архивированного официального репозитория и `--no-deps`. SDK импортируется,
  но `pip check` сообщает о недоступной metadata-зависимости `tinkoff`.
- Конфигурация локального запуска сделана переменной окружения; по умолчанию
  приложение использует SQLite, а PostgreSQL и Redis конфигурируются отдельно.
- Первая попытка Django-проверки остановилась из-за отсутствовавшего
  `django-filter` в локальной виртуальной среде. Зависимости из обновлённого
  `requirements.txt` установлены; повторные проверки прошли.
- Не запускались запросы к реальному Tinkoff API, PostgreSQL и Redis. Их результаты
  не приписываются агенту.

## Проверки и фактические результаты

В Python 3.11.9 выполнены:

- `pip install -r requirements.txt` — успешно;
- установка SDK из закреплённого git-коммита — успешно;
- import smoke для `Client`, `CandleInterval` и `now` — успешно;
- `manage.py check` — успешно;
- `manage.py makemigrations --check --dry-run` — миграции соответствуют моделям;
- `manage.py test` — 37 тестов завершились успешно на SQLite, включая применение
  миграций тестовым runner;
- `manage.py migrate --noinput` на отдельной SQLite-БД и запуск
  `manage.py runserver` — успешны; GET `/` вернул HTTP 200;
- `pip check` — неуспешен только из-за объявленной SDK metadata-зависимости
  `tinkoff`, недоступной в используемом индексе.

Реальное подключение к PostgreSQL, Redis, worker/Beat и Tinkoff API не тестировалось.
Локальная существующая база `db.sqlite3` не изменялась. Продолжительность выполнения
и число пользовательских итераций отдельно не замерялись, поэтому числовая оценка
времени/итераций не приводится.

## Сравнение со вторым агентом

Сравнительная оценка пока не составлена: результаты второй ветки не предоставлены
для анализа, а пользователь поручил её не трогать. Заполнять её предположениями
было бы недостоверно. Для выполнения задания №5 нужны отчёт второго агента или
доступные пользователю результаты его анализа, diff, тестов и затраченных ресурсов.
Пользователь подтвердил, что пока данных нет и сравнение следует оставить
незавершённым.
