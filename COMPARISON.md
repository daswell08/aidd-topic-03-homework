# Сравнение AI Coding Agents: GitHub Copilot и Cursor

## 1. Цель сравнения

В рамках домашнего задания были использованы два независимых AI Coding
Agent: GitHub Copilot и Cursor. Оба агента работали с учебным
веб-приложением Investing Demo на Django. Их задачами были анализ
исходного проекта, восстановление функциональных требований, аудит и
исправление ошибок, запуск и проверка приложения, а также реализация
новой функциональности.

Работа агентов велась раздельно. Результаты сохранены в отдельных
Git-ветках: `copilot-work` и `cursor-agent`. Изменения между ветками не
объединялись.

## 3. Реализованная функциональность

### GitHub Copilot

Copilot реализовал четыре направления новой функциональности:

1.  История рыночных цен.
2.  Виртуальный инвестиционный портфель.
3.  Список наблюдения и уведомления о достижении ценовых уровней.
4.  Симулятор инвестиционных стратегий.

В отчёте Copilot также зафиксированы успешные проверки: 35 тестов,
проверки Django и миграций, запуск сервера на отдельной базе SQLite и
получение ответа `HTTP 200` от главной страницы.

### Cursor

Cursor реализовал два направления:

1.  История рыночных цен с сохранением снимков и отображением изменений
    за периоды.
2.  Виртуальный портфель с покупкой и продажей акций, расчётом средней
    цены и учётом операций.

В отчёте Cursor указано, что 26 тестов завершились успешно. Два других
направления --- список наблюдения и симулятор стратегий --- не были
реализованы. Во время работы агент столкнулся с ограничением бесплатной
квоты. Поэтому его результат по заданию 4 является частичным.

## 4. Качество проверки и ограничения

Оба агента использовали автоматические тесты и проверки Django. При этом
результаты нельзя считать полностью одинаковыми по объёму: у агентов
разное количество тестов и разные дополнительные проверки.

Для обоих решений остались ограничения, связанные с внешней средой:

-   не удалось полноценно проверить получение реальных котировок через
    Tinkoff Invest API;
-   для проверки требуются токен и доступный SDK;
-   работа PostgreSQL, Redis и фоновых процессов Celery не была
    полностью проверена в реальной инфраструктуре.

В отчёте Cursor отдельно указаны проблемы установки Tinkoff SDK и
отсутствие Docker в среде. В отчёте Copilot также зафиксированы
ограничения проверки внешнего API и зависимостей.

## 5. Самостоятельность и ход работы

Оба агента получили исходное задание и самостоятельно анализировали
проект, выбирали способ реализации и вносили изменения.

Cursor выбрал две связанные функции --- историю цен и виртуальный
портфель. В его отчёте описаны пять итераций работы и примерная оценка
времени 1,5--2,5 часа. Эта оценка является приблизительной, а не точным
измерением.

Copilot выполнил более полный объём задания 4. По имеющимся данным его
работа включала анализ, модернизацию, реализацию функций, тестирование и
подготовку отчётов. Точное сопоставимое время работы и число итераций
для Copilot в доступных результатах не зафиксированы, поэтому
количественно сравнивать скорость агентов нельзя.

## 6. Преимущества и недостатки

### GitHub Copilot

**Преимущества:** - выполнил все четыре направления новой
функциональности; - подготовил отчёты по анализу и процессу работы; - в
отчёте зафиксированы тесты и дополнительные проверки запуска; -
результат охватывает больший объём задания 4.

**Недостатки и ограничения:** - проверка реального Tinkoff API и внешней
инфраструктуры также ограничена; - по имеющимся данным нельзя достоверно
сравнить точное время работы с Cursor.

### Cursor

**Преимущества:** - подготовил подробный анализ проекта и отчёт о
действиях; - реализовал историю цен и виртуальный портфель; - добавил
тесты для новой функциональности; - подробно зафиксировал проблемы
окружения и непроверенные сценарии.

**Недостатки и ограничения:** - выполнена только часть задания 4; -
список наблюдения и симулятор стратегий остались нереализованными; -
бесплатная квота ограничила продолжение работы; - живой браузерный
прогон не был завершён.

## 7. Итоговый вывод

По результатам этой работы GitHub Copilot показал более полный результат
выполнения домашнего задания: он реализовал все четыре направления новой
функциональности и предоставил отчёт о 35 успешно пройденных тестах и
дополнительных проверках.

Cursor также справился с анализом проекта, исправлением ряда проблем и
реализацией двух полезных функций --- истории цен и виртуального
портфеля. Однако из-за ограничения бесплатной квоты его работа над новой
функциональностью осталась частичной.

Таким образом, в рамках именно этого задания более результативным
оказался GitHub Copilot по полноте выполненных требований. Это не
означает, что он всегда лучше Cursor: сравнение относится к конкретному
проекту, доступным тарифам, ограничениям среды и результатам двух
запусков агентов.

Оба агента помогли ускорить анализ и разработку, но их результаты
требовали проверки человеком. Особенно важно отдельно проверять тесты,
миграции, безопасность настроек и работу с внешними сервисами, которые
не удалось проверить в данной среде.
